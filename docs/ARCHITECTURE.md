# 实现路径与取舍

## 接受语义先于搜索

模型的“接受”不仅由命名规则决定，还包括变量键恰好匹配、每值处于原域，以及中间整数运算有定义。`check_assignment` 直接检验这些条件；它不调用搜索器，也不相信搜索统计。它与搜索共享解释器语义，因此这不是两套完全独立数学实现；Python oracle 另行实现语义与完整解集核对。

部分赋值的 unbound 与已经确定的 undefined 分开表示。布尔 All/Any 在未知保护条件存在时不提前把 undefined 当作整体失败；例如 `any(1/0==0,x==1)` 在 x 未绑定时必须继续搜索，x=1 时成立。普通 Not 不反转 undefined；Holds 专门用于“规则无定义即拒绝”的验证语义。

## 对比两版原始域

先验证变量名集合一致，再构造各变量域的并集。不能简单把两个版本的规则都放在新域运行，因为旧版本不接受新增域值、空旧域也不是无限域。每版编译成 `holds(all(original-domain-tables, original-rules))`，用两个 0/1 indicator 的不等关系表示对称差。每个原始 AST 只嵌入一次，避免复制膨胀。

找到候选变化后，回到两版原始 `check_assignment` 分别验证，并记录真实命名违规。这个回放发现的是生成/编译路径不一致，不独自证明无遗漏；零变化等价结论依赖完整搜索。

## 搜索、最小化和诊断

搜索对每个未绑定变量尝试域值，运行部分规则检查，选支持值最少的变量。每次候选探测先扣预算，失败候选同样计数。分支退出后撤销赋值，保存见证时复制 Map。最坏仍为指数搜索，不宣称支持大规模 CP/SMT 性能。

分类两解即能证明多解；唯一和无解都需要穷尽。达到见证上限即标记 SolutionLimit，即使刚好只存在这么多个解也不冒称完整。优化保存当前最优见证而不存全部解，但不做隐藏的近似最优判定；只有穷尽才标记 optimal/minimal。

最近变化的目标是对每变量 `indicator(value!=baseline)` 求和。构造平衡加法树，避免 100/128 字段配置因线性嵌套越过深度限制。并列最优只保证确定性，未承诺字典序。

冲突说明固定原域，尝试逐条删除命名规则。剩余规则仍无解且搜索完整时才删除。某次删除检查预算不足就保留规则，并将 irreducible=false；它不是最小基数 UNSAT core。上述指标都不表示学生认知难度。

## 为什么不直接改旧生成器

旧版 `Family` 分派、Int64 有理数与贪心组卷不适合承载这些完整性语义。新包完全不导入旧代码，旧版留作兼容和透明历史。已有 CSP 库有更丰富传播能力；当前选择小型解释器以控制受检查算术和总化接受语义，未来可增加适配器，但不能用此选择宣称已有库无价值。
