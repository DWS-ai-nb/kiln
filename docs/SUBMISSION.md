# 项目说明（报名用一页版）

**项目名**：铸题 kiln
**一句话**：带适定性保证的可验证命题引擎——把「这道题应该长什么样」写成约束，反解出题目，并让每道题自带可机器复核的答案凭证。
**形态**：MoonBit 库 + CLI（不是刷题网站，不是题库系统）
**许可**：Apache-2.0

---

## 要解决的问题

出一张卷子，难的不是「写题」，是「它恰好是道好题」：有解、解唯一、没有增根、难度可控、和上周不重。

坏题只有三种形态，而三种都在真实试卷里反复出现：无解、多解（增根）、退化（十道题四道常数项为零）。现有题库工具几乎都停在「存题 + 抽题」，题是人写的，系统只负责索引。**难点不在抽，在造；不在造得出来，在造出来的题是良定的。**

## 技术要点

1. **生成器与验证器走两条不共享的推导路径**。生成侧从答案用韦达定理反解系数；验证侧从系数算判别式、开方、套求根公式再比对解集。同一个符号错误不会在两边同时发生并互相抵消。`moon test` 因此等价于全题库体检，不是抽查。
2. **适定性是判定，不是抽样**。存在与唯一是硬门槛；稳定（系数 ±1 扰动后仍是两个相异实根）是软信号，影响排序不影响收录。判不了的部分显式返回 `Undecidable`，不猜。
3. **结构指纹按「同解」而不是「同系数」**。`2x²-10x+12`、`x²-5x+6`、`-x²+5x-6` 是同一道题，指纹把它们合并；对一元多项式这个映射既 sound 又 complete。
4. **凭证是一个格式，不是内部细节**。`paper.json` 每道题带 `payload`，任何人用任何语言都能重算答案。仓库里有一份 112 行的 Python 参考实现，与 MoonBit 实现零共享，CI 强制两边结论一致。

## 与生态的关系

MoonBit 生态里符号计算（`maxima`、`symbit`）、排版（`typst`、`pagelayout`）、约束求解（`moonplan`、`cassowary`）都已成熟，本项目**不重造这些**。缺的是「命题」这一层：把已有能力装配起来，解决一个还没被建模的问题。

生态里已有 `moonmentor` 这样的学习记录工具（估计掌握度、安排练习），它需要题源；kiln 提供题源。两者是上下游，不是竞争。

## 怎么验证

```bash
moon update
moon check --target all --deny-warn
moon test --target js                 # 65 passed

moon run cmd/cli --target js -- gen --schema examples/quadratic.kiln --count 5 --seed 2 --out out
python3 tools/verify_reference.py out/paper.json    # 用 Python 独立复核
moon run cmd/cli --target js -- verify --file out/paper.json
```

已用干净克隆在只有 MoonBit 工具链的环境下验证过：`moon update` → `check` → `test` → `gen` → 两种语言分别校验，全部通过。

## 当前边界（如实说明）

- 只做可判定子集：一元二次方程、分式方程。不做几何证明、不做自然语言应用题、不做完整 CAS。
- 组卷是确定性贪心，不保证「有解时一定找到解」（NP-hard），但失败时给具体缺口，不返回残卷。
- 凭证校验的是**数学**：`payload` 与 `answers` 一致。题干文字是渲染层，不参与校验——这一点写在 `docs/CERTIFICATE.md` 里，不掩饰。
- 难度是经验模型，可解释但未用作答数据标定。
